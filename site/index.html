An open, agent-agnostic standard for choosing the right Agent Skills for a task, and a reference implementation that ties together superpowers, BMad Method, spec-kit, codegraph, Anthropic's skills and more, without copying any of them.

Why

Coding agents now load skills from many independent projects. A typical setup has 100+ skills that overlap: three build workflows, several reviewers, two kinds of brainstorming.

Overlapping descriptions

Agents pick skills by matching descriptions, so overlap makes them load the wrong skill or miss the right one.

A shrinking listing

Claude Code budgets the skill listing at about 1% of the context window and drops the least-used descriptions first, so matching gets worse as you install more.

Open Skill Standard adds the missing layer: which role a skill serves, which phase it acts in, and which artifacts it consumes and produces. From that, a router builds a short, ordered, explained chain for each task.

What you get

Four core skills, a CLI, and a registry that describes upstream skills as metadata, never copying them.

open-skill-router

Routes the task, announces the chain in one line, runs step 1 and records what ran.

open-skill-standards

Definition-of-done checklists, general and for each of the 28 roles.

open-skill-intel

Sends each question to the best source: codegraph, Context7, schemas, the web, your notes.

open-skill-learn

Remembers your lessons and preferences, locally, so future routes use them.

open-skill CLI

route, search, doctor, session, lint, audit, learn and more.

Registry

Adapters for upstream sources, role packs and model profiles, validated in CI.

How it works

The registry and your installed skills feed a local index; the router adds your project and your notes, then hands the agent an ordered chain with the reason for every step.

28 IT roles

Each role pack states the role's characteristic risk, its principles, the project files that suggest it, and its primary and alternative skills per phase. The same kind of request routes differently by role.

Parallel sessions, one shared graph

Several agent sessions can work on one project at once. Each declares the paths it works on; after an edit, open-skill session update refreshes one shared Graphify code graph and warns, never blocks, when the change reaches another session's scope.

Measured, not claimed

On held-out requests the router is scored against baselines and ablations with the same checks CI runs, and every number can be reproduced with python -m open_skill.benchmark.

Get started

Three steps in Claude Code; other agents that load Agent Skills work too (see the list).

# 1. Install the skills (Claude Code); or: npx skills add VoKhoiNhon/open-skill-standard -g
/plugin marketplace add VoKhoiNhon/open-skill-standard
/plugin install open-skill@open-skill-standard

# 2. Tell it your role(s); this also seeds starter knowledge for them
uvx --from git+https://github.com/VoKhoiNhon/open-skill-standard@v0.7.2 open-skill init --role data-engineer=0.7 --role data-analyst=0.3

# 3. In your agent, inside any project
/open-skill-router add a pipeline that loads orders into the warehouse
